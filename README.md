# One Work Winning Hub (OWWH) — Demo

A demo of the **One Work Winning Hub**: one place to search, share and govern work-winning knowledge (case studies, project profiles, bid submissions, contacts and Salesforce opportunities) across five sectors, with sector-first permissions.

- **Business requirements:** [`BRD.md`](BRD.md)
- **Product requirements:** [`PRD.md`](PRD.md)
- **Brand guidelines:** [`BRAND.md`](BRAND.md)
- **Source data:** `salesforce_synthetic_cut.xlsx` (Salesforce Opportunity export, 284 columns)

## Quick start

**Prerequisites:** Python 3.11+ and Node.js 20.19+ (required by Vite 7).

```bash
npm run setup               # creates .venv, installs dependencies, loads ONLY the real Salesforce export
npm run setup --synthetic   # same, plus generated demo data (synthetic opportunities and content)
npm run dev                 # Flask API on :5001 + Vite on :5173, run together with concurrently
```

Open http://localhost:5173.

**Which data mode?** By default the database holds only what is in `salesforce_synthetic_cut.xlsx`: 8 opportunities and the 9 people named in them. There is no content library until someone submits content. Add `--synthetic` for a fuller demo with 142 generated opportunities, case studies, project profiles, bid submissions and governance queues. You can switch at any time by re-running `npm run seed` or `npm run seed:synthetic`.

## Scripts

| Command | What it does |
|---|---|
| `npm run setup` | Create `.venv`, `pip install -r server/requirements.txt`, install root and client npm packages, seed **real data only** |
| `npm run setup --synthetic` | As above, but seed with synthetic demo data too (alias: `npm run setup:synthetic`) |
| `npm run seed` | Rebuild `data/owwh.db` from the xlsx, real data only (deterministic, safe to re-run) |
| `npm run seed --synthetic` | Rebuild with synthetic demo data too (alias: `npm run seed:synthetic`) |
| `npm run dev` | Run `flask --debug` (port 5001) and the Vite dev server (port 5173) together; Vite proxies `/api` to Flask |
| `npm run build` | Type-check and build the React app into `client/dist` |
| `npm start` | Build, then serve the app and the API with **gunicorn** on http://localhost:8000 |
| `npm run build:share` | Build **`share/owwh-real.html`**, a single self-contained file with only the real Salesforce export, which you can email (see below) |
| `npm run build:share --synthetic` | Build **`share/owwh-synthetic.html`**, the same but with synthetic demo data (alias: `npm run build:share:synthetic`) |
| `npm run test:parity` | Check that the in-browser API used by the shareable file returns the same results as the Flask API |

## Sharing a single HTML file

```bash
npm run build:share               # → share/owwh-real.html       real Salesforce export only (~2.6 MB)
npm run build:share --synthetic   # → share/owwh-synthetic.html  real + synthetic demo data (~3 MB, ~1.2 MB zipped)
```

Each command creates one HTML file that contains the whole app and its dataset. The data options match `npm run seed`: real data by default, and generated demo data only with `--synthetic`. The file name and the sidebar note show which dataset a file contains. Recipients open it in Chrome, Edge, Firefox or Safari. It needs no install, server or network connection; fonts fall back to system fonts when offline.

How it works:

1. `server/export_offline.py` builds the database (with `--synthetic` if requested), compresses it, and exports the `/api/meta` response and backend constants to `client/offline-data/`.
2. `vite build --mode share` inlines all JavaScript, CSS, the logo, the SQLite WebAssembly engine and the compressed database into one file (`vite-plugin-singlefile`).
3. In the page, `client/src/offline/` opens the database in memory and answers the app's API calls with the same SQL as the Flask routes. URLs use `#/…` so the file works when opened from disk.

Search, filters, persona switching, permissions and submissions all work. Changes last until the page is closed, and every recipient starts from the same data.

`client/src/offline/routes.ts` and `search.ts` are a TypeScript port of the Flask routes. **If you change an API route, update the port too** and run `npm run test:parity`. It replays 57 requests (reads, permission denials, validation errors, and a submit → approve → review → edit flow) against both versions on the same database and fails on any difference.

Some email systems (often Outlook) block `.html` attachments. If yours does, zip the file or share it from OneDrive/SharePoint.

## Data

`npm run seed` builds the database from `salesforce_synthetic_cut.xlsx`.

**Default (real data only):**

- **`opportunities`** has all **284 Salesforce columns with their original names** and the 8 real rows, unchanged apart from converting dates to ISO-8601.
- **Contacts** are the 9 people named in the export's populated people fields. Their title comes from their role in the data, and their location from the opportunity's region.
- **No generated data:** no content items and no invented sector owners (shown as "Not nominated").
- **App configuration** the app needs to run is always loaded: the field dictionary (`sf_field_meta`, which gives each column a readable label, group and type), the five BRD sectors, the persona list and sector administrators (the sign-in stand-in), and the business-unit options for the Submit form.

**With `--synthetic`, the seed also adds:**

- **142 synthetic opportunities** so search and filtering have enough to work with. Generation uses a fixed random seed, so every run produces the same data.
- **Only columns that hold data in the export are generated.** 84 of the 284 columns have a value in at least one real row. Synthetic rows fill only those 84; the other 200 keep exactly what the export has (blank, `0` or `[]`), because they may not be used at all. For example, only the QLD and VIC revenue-split columns are populated, so synthetic opportunities elsewhere have no revenue split, and FY forecasts, margins, JV, bonding and estimator/legal columns stay empty. The seed resets those columns as a final step, so the rule cannot be broken by accident.
- **People named in the export** (proposal managers, bid writers, tender managers) appear only on the real rows. Synthetic rows use invented names.
- **Derived OWWH content** (`content_items`):
  - a project profile for every won opportunity
  - case studies for a subset of the won ones
  - a bid submission, with lessons learned, for every closed opportunity
  - templates, good-news stories, images and a capability statement for each sector
- **Synthetic contacts:** the invented people on synthetic rows, plus delivery and technical leads on won work.
- **Governance data:** sector content owners and backup administrators, review and expiry dates on the BRD cycles, approval status and version history.

### Data source labels

Every opportunity, content item and contact carries a badge, and Search, Opportunities and Contacts can filter by it:

| Badge | Meaning |
|---|---|
| **Salesforce export** | A row from `salesforce_synthetic_cut.xlsx`, or a person named in it |
| **Synthetic** | Generated for the demo. Content derived from a real opportunity keeps that opportunity's metadata, but its narrative text is generated |
| **User submitted** | Entered through the Submit page |

The 8 real rows also have `BRS_Opportunity_Number__c` below 16500; synthetic rows start at 16500.

The PRD (§5) has the full mapping from Salesforce fields to OWWH fields.

Visibility rules (BRD §7):

- **Sector only** (the default for new content): only the originating sector can see it.
- **Shared:** the originating sector plus the sectors it is shared with.
- **Enterprise:** everyone.
- Content with a **restricted flag** (pricing, current tender, government, NDA, client-sensitive, referee, CV) and **pending** content stay within the originating sector, whatever their visibility setting.
- Opportunities with `Visibility_Classification__c = Restricted` are visible only to their own sector.
- Items you can't see return 404.

## Demo walkthrough

1. **Search:** on Home, try `water treatment projects in VIC`, `case studies in QLD over $5m` or `who has worked with Optus`. The parser turns the phrase into filters you can remove one at a time.
2. **Opportunity detail:** open *Sandy Flat Water Treatment and Active Management* (one of the real xlsx rows) to see key dates, the pursuit team, the revenue split and every populated Salesforce field. Turn on **Show empty fields** to see all 284.
3. **Permissions:** switch from a Transport persona to a Telecommunications persona. Transport sector-only content and Restricted opportunities disappear from search and the library.
4. **Submit content:** go through the five-step form as a Bid Manager. Missing mandatory metadata blocks you, and the review step warns about similar content. The new item is *pending* and visible only to your sector.
5. **Governance:** switch to that sector's admin persona, approve the item from the Approvals queue, and work through the overdue reviews. Enterprise Admin can filter by sector and read the audit log.

## API

All endpoints are under `/api` and read the persona from the `X-OWWH-User` header (default `u-transport-bm`).

| Method | Path | Purpose |
|---|---|---|
| GET | `/meta` | Sectors, personas, filter options |
| GET | `/stats` | Home-page KPIs, recent content, sector tiles |
| GET | `/search?q=&parse=&doc_type=&sector=&region=&client=&service_line=&status=&value_range=&value_min=&value_max=` | Search with facets and parsed filter chips (`parse=0` turns off natural-language parsing) |
| GET / POST | `/content` | List / create content (create checks the mandatory metadata) |
| GET | `/content/similar?title=` | Possible duplicates |
| GET / PATCH | `/content/:id` | Detail / update (adds a new version) |
| POST | `/content/:id/approve` | `{"decision": "approve" \| "reject"}` (sector admin only) |
| POST | `/content/:id/review` | Mark as reviewed (sets the next review date) |
| GET | `/opportunities`, `/opportunities/stats`, `/opportunities/:id` | Pipeline list, charts, full field detail |
| GET | `/contacts`, `/contacts/:id` | Directory and profile |
| GET | `/governance` | Review, expiry, approval and metadata queues; sector roster |
| GET | `/audit` | Audit log (admins only) |

Example:

```bash
curl -s "http://localhost:5173/api/search?q=NBN" -H "X-OWWH-User: u-telco-pw"
```

## Notes and troubleshooting

- **Simulated integrations:** SharePoint teamsite links, Entra ID sign-in and Teams notifications are mocked, as described in PRD §4.8.
- **Port 5000:** the API uses port 5001 because macOS AirPlay Receiver takes port 5000.
- **Charts with no axes:** Recharts 2 needs `react-is` to match React 19. `client/package.json` pins it with an `overrides` entry. If charts render without axes, run `rm -rf client/node_modules/.vite` and restart `npm run dev`.
- **Reset the data:** `npm run seed` (or `npm run seed:synthetic`) rebuilds the database and removes anything submitted through the app.
- **The `--synthetic` flag:** npm passes unknown flags such as `--synthetic` to scripts as the `npm_config_synthetic` environment variable, which the seed reads. If a future npm version stops supporting this, use the `setup:synthetic` / `seed:synthetic` aliases instead.
- **Out of scope (deferred in BRD §12):** AI search and proposal assistance, chatbot, advanced analytics. The search parser is rule-based on purpose.
